## 5. 要走 REA，需要什么

REA（v6.8.0 / Ghidra 12.1.4）已在本机运行，但它**只分析本地产物**。要真正拆这个 App，需要以下任一：

| 产物 | 获得方式 | REA 能做什么 |
| --- | --- | --- |
| 已解密的 `.ipa` | 自己的设备 + 越狱/脱壳工具导出 | `inspect_artifact` 盘点资源、`inspect_macho` 看依赖与符号、`open_binary` 反编译 arm64 |
| App 沙盒数据 | 设备备份 / 文件 App 导出 | `inspect_sqlite_database` 看词库表结构 |
| Android `.apk` | 各应用商店公开下载 | `inspect_artifact` + `identify_flutter_build` / `inspect_dart_aot`，若为 Flutter 可取字符串与资源 |
| 网络抓包 | 自己的设备 + mitmproxy | `inspect_web_network_capture` 看接口与词库下发 |

> **更新（v0.3）**：已拿到 Android 包 `shiri_2.7.6.apk`（SHA-256 `2a184077…4b5f5`），静态分析结果见 [ARCHITECTURE.md](ARCHITECTURE.md)。iOS 店包仍未取得，iOS 相关结论不变。
> 商店包体受 FairPlay 加密，直接下载的 `.ipa` 内的 Mach-O 是加密段，静态分析拿不到有效代码——所以「下载了商店包」并不等于「能反编译」。Android APK 不受此限，这也是本次能推进的原因。

### 5.1 本机实测的能力边界（REA v6.8.0 / Ghidra 12.1.4 / Windows 11）

| 能力 | 状态 | 依据 |
| --- | --- | --- |
| 归档盘点（IPA / APK / ZIP 成员、哈希） | 可用 | `rea-artifact-graph` 已就绪 |
| 原生 Mach-O 反编译 | **不可用** | Windows 的 Ghidra 桥只接受 PE / raw 6502；`inspect_macho`、`inspect_signature` 等要求 macOS |
| SQLite 词库读取 | 可用 | `inspect_sqlite_database` 已就绪 |
| 网络抓包分析 | 可用 | `inspect_web_network_capture` 已就绪 |
| Android APK 类/方法分析 | 不可用 | 缺 caller-supplied JADX JAR 与 apktool |
| Flutter Dart AOT 字符串 | 可用 | `identify_flutter_build` / `inspect_dart_aot` 已就绪 |
| adb 动态调试 | 不可用 | PATH 上没有 `adb` |

结论：**在这台 Windows 机器上走 iOS 路线，最多只能做归档盘点与资源清点，拿不到伪代码。** 真要做代码级还原，得换 macOS，或者在 Linux/macOS 上跑 Ghidra 直接吃 Mach-O。Android 路线（如果有 APK）反而是这台机器上更现实的入口——前提是补齐 JADX 与 apktool。
